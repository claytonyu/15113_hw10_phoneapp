# Field Notes specification review

Reviewed against `SPEC.md` by reading the application code. `[PASS]` means the implementation is present in the code, not that it was exercised on a device. `[FAIL]` identifies a concrete mismatch or defect; `[WARN]` identifies a limitation, uncertainty, or risk. No iOS or Android runtime testing was performed.

1. **[FAIL] Location at button press.** In follow mode, `src/hooks/use-map-location.ts:87-102` accepts a fix up to 30 seconds old, so a moving user can save a note or photo at a previous location. If it requests a new fix, the result can instead represent a point several seconds *after* the tap. `src/components/field-map.tsx:88-98` does freeze the resulting coordinates before opening the editor, but does not meet the requested sampling moment (`SPEC.md:20-21`).
2. **[FAIL] Permanent photo deletion on file errors.** `src/lib/entries-db.ts:118-132` suppresses file deletion failures, while `src/lib/entries-db.ts:171-175` reports deletion success after removing the database row. The photo disappears from the app even if its image still exists on disk; retries depend on a future cleanup. This falls short of permanent deletion (`SPEC.md:27`) and leaves no visible error or immediate retry.
3. **[WARN] Visible map entries and clustering.** `src/lib/map-markers.ts:25-38` filters and clusters using a linear latitude/longitude approximation rather than the map provider's actual projection. At wide zoom levels or high latitudes, an entry can be filtered out despite being visible, or grouped at the wrong screen spacing. Grid boundaries can also leave nearby pins ungrouped. The grouping intent exists (`src/components/field-map.tsx:167-177`), but the guarantee for all visible notes (`SPEC.md:15`) is not established.
4. **[WARN] First-run and unavailable-location placement.** `src/components/field-map.tsx:37,76-85` starts in follow mode but silently uses the map center when permission has not been granted; the initial center is latitude 20, longitude 0 (`src/components/field-map.tsx:17,33`). A first-time user who has not tapped “Use location” can therefore create a geographically incorrect entry. When the map is not ready, the same path silently saves without coordinates. Panning to choose a location is supported, but the ambiguous permission exception in `SPEC.md:81` should be clarified.
5. **[PASS] Main map and current location.** `src/app/index.tsx:1-2` makes the map the entry route. With foreground permission, `src/components/field-map.tsx:147-150` enables the user-location indicator, and `src/hooks/use-map-location.ts:37-71` subscribes to foreground position updates (`SPEC.md:14,16-17`). Permission must first be requested with the location control (`src/components/field-map.tsx:51-67`).
6. **[PASS] Follow and explore controls.** `src/components/field-map.tsx:43-49,137-165` follows position updates, exits follow mode on pan, multitouch, double press or recognized map gesture, and offers a control to resume (`SPEC.md:17-18`). Actual gesture behavior on both map providers remains untested.
7. **[PASS] Long press and toolbar entry placement.** Online long presses capture the touched coordinate and offer note or photo creation (`src/components/field-map.tsx:106-115,165`). The toolbar offers labeled plus and camera actions and uses the current map center in browse mode (`src/components/field-map.tsx:75-85,187-190`). Follow-mode timing has the defect in finding 1; offline entries deliberately have no coordinates (`SPEC.md:19-21,80`).
8. **[PASS] Camera review.** `src/app/camera.tsx:74-113,134-164` captures an image, shows a preview, saves it or discards it for a retake; leaving the screen also attempts to discard the temporary capture (`src/app/camera.tsx:47-53`) (`SPEC.md:24`). Camera permission, mounting and capture errors have user-facing handling (`src/app/camera.tsx:66-71,123-129,146-147`).
9. **[PASS] Photo viewing and editing.** `src/app/photo.tsx:15-43` opens the saved image, provides replacement and deletion, and `src/components/zoomable-photo.tsx:24-53,64-81` provides pinch, pan and a zoom button (`SPEC.md:9,27`). See finding 2 for the permanent-file-deletion failure case.
10. **[PASS] Note editing.** `src/app/note.tsx:26-43,57-94` provides title and multiline body fields, saving, editing and confirmed deletion without showing the map; `src/lib/entries-db.ts:93-115` persists edits and updates `modified` (`SPEC.md:9,30-33`). Save and delete errors are surfaced while retaining the draft.
11. **[PASS] All Notes navigation and presentation.** `src/app/all-notes.tsx:16-34,39-69` renders a vertical `FlatList` of notes and photos, opens the respective detail route, shows titles and photo thumbnails, and includes unlocated entries (`SPEC.md:35-38,80`).
12. **[WARN] Creation-time ordering.** Database reload sorts by `created DESC, id DESC` (`src/lib/entries-db.ts:80-90`), but newly saved entries are always prepended (`src/lib/journal-provider.tsx:44-48`). If the device clock moves backwards, or timestamps tie, the live list can differ from the specified timestamp order and from the order after restart (`SPEC.md:37`).
13. **[PASS] Entity model and persistence.** Separate SQLite `notes` and `photos` tables contain IDs, timestamps and optional coordinates; notes store title, body and modified time, while photos store a filename (`src/lib/entries-db.ts:20-43,93-115,135-164`). Image bytes are stored in an app-private document file rather than in SQLite (`src/lib/photo-files.ts:4-13`); the database retains the image reference (`SPEC.md:40-56,61`).
14. **[PASS] Local architecture and specified libraries.** The journal uses `expo-sqlite`, captures with `expo-camera`, and renders maps with `react-native-maps` (`src/lib/entries-db.ts:2-3`, `src/app/camera.tsx:2`, `src/components/field-map.tsx:6`). No application backend or authentication flow is implemented. Map imagery and network status still use network services, consistent with the spec's offline-map exception (`SPEC.md:58-62,79-80`).
15. **[PASS] Visual direction.** The shared palette uses beige paper and yellow-orange accents (`src/constants/field-notes-theme.ts:2-9`), with simple system text and restrained controls (`src/app/all-notes.tsx:46-66`, `src/components/map-controls.tsx:23-31`) (`SPEC.md:64-68`). The field-notes feel and typography are subjective and need visual review on devices.
16. **[WARN] iOS and Android targets.** The code uses cross-platform React Native components, native map/camera libraries and platform-specific symbols (`src/components/field-map.tsx:6`, `src/app/camera.tsx:2`, `src/components/field-map.tsx:188-190`); the SDK 58 [map documentation](https://docs.expo.dev/versions/v58.0.0/sdk/map-view/) lists both platforms and Expo Go. There is no evidence in this review that the complete app was run on either platform, so platform acceptance and Expo Go compatibility are not verified (`SPEC.md:70-73`).
17. **[PASS] Notifications and background tasks.** No push-notification or background-task implementation was found in `src`; the location watcher is removed when the map loses focus or the app is inactive (`src/hooks/use-map-location.ts:27-28,37-40,67-71`) (`SPEC.md:75-76`).
18. **[PASS] Offline access.** `src/components/field-map.tsx:29-30,78-80,106-110,133,181-190` displays offline status, keeps All Notes accessible, and creates unlocated entries offline. `src/lib/map-markers.ts:25-26` excludes those entries from the map, while the list includes them (`src/app/all-notes.tsx:19-22,67`) (`SPEC.md:78-80`). Network state can initially be unknown, so offline classification is only as current as the network hook's reported state.
19. **[WARN] Scalability and maintainability.** `src/lib/entries-db.ts:81-90` loads every note body and photo record at startup; `src/lib/map-markers.ts:25-38` scans the entire collection on each completed map-region change. The list itself is virtualized, but large journals can increase startup time, memory use and map interaction cost. There are no project test scripts in `package.json:43-49`; behavior such as clustering, cleanup and location placement is not covered by visible automated tests.
20. **[PASS] Static checks.** The installed local Expo CLI lint command (`./node_modules/.bin/expo lint`) and TypeScript check (`./node_modules/.bin/tsc --noEmit`) both completed successfully. These checks do not verify camera, GPS, offline behavior, map rendering, or device-specific interaction.
